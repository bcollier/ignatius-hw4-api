Making a retreat from a document

A PDF, Word file, photo of a page, pasted text or shared Google Doc becomes a day-by-day plan.

Server · FastAPI on Render
  1. POST /api/retreats (the file or google_doc link, model, planning prompt, build options, series) answers 202 at once; the work goes on in the background.
  2. app/extract.py pulls out the text, pictures and scanned pages (PyMuPDF for PDFs, python-docx for Word; photos as images). app/google_docs.py downloads a shared Doc.
  3. app/pipeline.py saves the retreat and its source, then llm.plan_retreat asks the model for a plan in a strict JSON schema: title, days, each day's passage word for word, grace, focus and painting.
  4. Too long for one reply? The model marks each passage's first and last ten words and the app copies the text between them from the document.
  5. With build options, every day is then built at once (feature 3). The retreat page polls GET /api/retreats/{id} for progress.
Data · Supabase, private (server key only)
  • retreatsOne row per retreat: id, user_id, title, and data jsonb, the whole retreat (plan, days, status, costs)
  • bucket retreats{user}/{retreat}/source.json, scan{i}.png, image{i}.jpg
  • profile{user}/user info.md: About me, added to every call when the retreat is personal
  • llm_callsEvery model call: prompt, reply, tokens, seconds, cost
